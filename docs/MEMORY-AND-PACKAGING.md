# 内存与 Windows Release 包

## 内存优化

- 表情目录由启动时解析改为首次进入表情页面时解析，仍使用 OnceLock 复用。
- 快捷面板仅选中记录时不解码隐藏预览；打开预览才读取并生成。
- 关闭侧预览时释放服务的预览缓存、窗口 RGBA/BGRA 图像、编辑器文本与 GPUI sprite atlas 条目。更换记录、翻页也释放旧 atlas 图像。
- 每次预览返回代次，关闭只取消自己的代次；旧窗口关闭不能取消其他窗口的新预览。后台提交结果前在同一锁内检查代次，避免关闭后重新发布已完成的图片。
- 历史列表继续只保留有限长度元数据，原图与完整内容仍按需从加密数据库读取。未降低图片预览分辨率、删除格式支持或压缩历史内容。

服务测试覆盖预览 Arc 最终释放、旧代次不清除新预览、取消后后台任务不重新发布。操作系统分配器和 GPU 驱动可能保留已释放页供复用，因此任务管理器工作集不保证立即等量下降。

## 构建与压缩

运行 `pwsh -File scripts/package-windows.ps1`（PowerShell 7.2+），默认使用 `D:\devTools\upx\upx.exe`，可用 `-Upx` 指定路径。

Release 使用 opt-level=s、thin LTO、单代码生成单元与 strip，保留 unwind 行为。脚本只压缩 dist 下新建分发目录中的 EXE 副本，保留 target/release 原件，执行 `upx -t`，分发 PDFium 原始 DLL 与许可，生成 SHA256 清单、build-info.json 和 ZIP，并校验 ZIP 中 EXE 哈希。

UPX 减少磁盘体积，不承诺减少运行内存；解压后的代码仍须驻留。包内不含用户数据库、密钥、测试数据或截图。

`-NoUpx` 生成未压缩 Release 包；`-SkipBuild` 复用刚完成的构建。推荐日常使用未压缩 Release 降低内存，UPX 版适合优先减少解压后磁盘占用。

## 本机验证结果（2026-10-25）

暂停采集，避免当前系统剪贴板内容变化影响结果。每次预热5秒、间隔500ms采样10次取中位数。后台为同一合成测试库副本；引导窗口为空的暂停采集测试库。旧 Debug 的 SHA-256 与此前基线一致。MiB = 1024²字节，单次本机对比不代表长期内存上限。

| 场景 | 旧 Debug 工作集 / 私有内存 | 新 Release 工作集 / 私有内存 | UPX Release 工作集 / 私有内存 |
|---|---|---|---|
| 仅托盘后台 | 68.5 / 52.7 MiB | 51.7 / 51.4 MiB | 76.1 / 83.1 MiB |
| 引导窗口 | 105.4 / 84.4 MiB | 84.0 / 82.4 MiB | 104.8 / 114.0 MiB |

Release 后台工作集在这次测量中降低约24.5%。这是构建优化和按需加载等改动的合并效果，不能单独归因于某一项。UPX 私有内存明显更高，不作为内存优化手段。预览关闭后的缓存释放另由 Weak 引用和原生 RenderImage 引用释放探针验证，不能用启动测量代替大图预览测量。原始采样及对应EXE哈希见memory-report.json。

EXE：旧 Debug 83,699,200 字节；Release 33,325,056 字节；UPX 8,199,680 字节。UPX 比 Release 减少75.4%。PDFium DLL保持原样，包目录两页PDF渲染及翻页探针通过。UPX完整性、独立数据库后台启动和原生窗口创建通过。14项核心测试、2项UI测试、Clippy通过。首次指南、普通重启管理窗口、后台重启无窗口的原生探针通过；真实钉钉回贴及跨平台发布本轮未重测。

## 追加交互修复

- 置顶/收藏先在共享快照中立即更新并重绘，按代次后台持久化；刷新覆盖尚未落盘的最新状态，旧命令完成不覆盖新操作。失败从数据库恢复真实状态并显示错误，队列满时不做虚假更新。真实服务线程搭配300ms慢回贴后端的回归先红后绿，立即反馈低于100ms；连续置顶、取消置顶、收藏、取消收藏及重开持久化通过。这不等于已测得用户当前机器的物理点击至显示延迟。
- 分组数字恢复到行末，右侧内边距24px，避开滚动条。
- 图片行使用96×64以内缩略图代替“图片”文字。仅可见行请求，后台从加密载荷生成，RAM缓存最多48张（原始像素最多约1.13MiB），不额外保存明文文件；每个窗口复用渲染图像，淘汰时调用atlas释放API。
- 等待加密设置读取完成后选择初始窗口。首次展示记录guide_seen，即使未点完指南也不在下次启动重复弹出；已完成旧版引导的用户也不会再自动打开。普通重启打开管理窗口，后台重启保持托盘。关于页面提供“查看使用指南”，仍复用单例窗口。
- Windows DirectX atlas后端未实现测试contains查询（默认总为false），因此未把该查询用作GPU释放成功证据。原生探针检查关闭后实际RenderImage强引用归零，同时保存打开图片的真实渲染图；GPU驱动保留的分配量未独立测量。

缩略图解码使用单独后台线程和容量1的有界队列，不在UI线程或数据库写入线程解码；数据库线程只读取载荷。开启/取消钉住与收藏分别使用Pin/PinOff、Star/StarOff图标，列表与详情保持一致。
