# 首次快捷面板尺寸与开关状态修复

2026-10-25。

## 首次打开过宽

新增原生回归走生产 `open_window(Kind::Quick)`，不调用截图入口原先的 `settle_size`。修复前实测首开1424×745，执行生产打开/关闭预览后为360×540，与用户截图及复现步骤一致。证据：test-data/initial-size-before/initial-size-result.json。

根因是Windows窗口以CW_USEDEFAULT创建；show=false时GPUI将目标初始位置/尺寸暂存，应用自身的“不激活显示”路径直接SetWindowPos且带NOSIZE，未应用这份初始尺寸。预览关闭调用GPUI resize后才恢复正确值。

现在先在隐藏窗口安装焦点保护，调用GPUI resize，再异步等待WM_SIZE更新可绘制区域为360×540，随后定位并不激活显示。窗口保持隐藏直到尺寸匹配，最多等待2秒；失败显示明确错误，不改为抢焦点打开。没有修改GPUI依赖或重复实现窗口边框/DPI尺寸换算。

同一个真实首次显示探针修复后通过：首开360×540，预览关闭后360×540。实际首开图：test-data/initial-size-after/first-open.png。

复现方式：以合成fixture运行带ui-capture的 `--ui-review`，设置 `X_CLIPBOARD_UI_REVIEW_INITIAL_SIZE=1` 和独立输出目录。该入口停止平台采集/钩子，不在用户数据库执行测试。

## 开关难辨认

GPUI Switch的switch token表示“关闭”轨道，之前误设为黄色，导致开启和关闭均呈黄/金色。改为浅色中性灰/深色灰轨道，白色滑块；开启使用按钮强调色（默认黄色）。设置行添加“已开启/已关闭”文字，保持原生Switch点击和键盘行为。

浅深主题均生成并逐张检查同时含开启与关闭状态的原生图：docs/native-screenshots/window-fixes/settings-general-switches-light.png、settings-general-switches-dark.png。引导中的开关也使用相同开启强调色及全局关闭轨道。

圆形黄色应用图标仍然保留；本次没有回退主题、Kbd、图标或窗口焦点保护。


## 2026-10-25 单例、托盘与响应修复

原生探针复现管理窗口回调中再次导航创建第二个 HWND。现在延后导航至回调释放借用，已有句柄更新失败也不创建重复窗口。管理、快捷、设置、引导、托盘五类窗口重复打开均复用原始 HWND；关于页面复用设置窗口。标题栏下拉菜单禁用当前窗口的导航，关于页面同时禁用关于入口。

Windows 托盘改为 GPUI 菜单，跟随应用主题。开启记录时显示暂停图标与“暂停记录”，暂停后显示播放图标与“开启记录”。后台原子切换读取最新状态，已排队的采集也检查暂停状态。其他平台保留原生菜单。

置顶、最近复制的数量紧跟分组标题。置顶与收藏按主键更新单条记录；未超容量时局部刷新快照，避免每次扫描历史全表。超容量仍执行清理规则。2001条合成加密记录的单条更新中位耗时由25.9ms降至3.7ms；这是数据库基准，不是点击至显示的端到端耗时。

验证：14项核心测试通过，另一个延迟基准按需运行通过；2项UI测试通过；Clippy全目标零警告，默认Debug构建通过。首次尺寸与五类窗口单例原生探针通过。生成88张原生图，抽查默认明暗托盘、暂停状态、当前导航禁用与分组数量。截图生成不等于全部主题视觉验收；真实系统托盘鼠标操作、高DPI及非Windows平台仍需实机验证。
