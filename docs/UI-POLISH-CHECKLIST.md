## 专用原生渲染入口

此路径只在 Windows `ui-capture` feature 下启用。它使用真实 GPUI `Desktop` 渲染和 `Window::render_to_image`，不是 HTML 截图。不向记事本、钉钉或其他应用键入内容。

```powershell
# 必须是尚不存在的新目录；不会覆盖已有目录或数据库
cargo run --locked --no-default-features --example review_fixture -- test-data/ui-polish-review-001
cargo build --locked --features ui-capture
# PDFium DLL 需要在 EXE 同目录，沿用 scripts/fetch_pdfium.py
$env:X_CLIPBOARD_DATA_DIR = "$PWD/test-data/ui-polish-review-001"
$env:X_CLIPBOARD_UI_REVIEW_OUTPUT = "$PWD/docs/native-screenshots/polish"
target/debug/x-clipboard.exe --ui-review
```

fixture 创建加密库及全部合成文件，实际监听设置为暂停，使用不与默认 Win+V 相同的测试快捷键；截图入口校验 `UI-REVIEW-FIXTURE.json` 的合成标记和 ID 白名单，随后停止平台监听/键盘钩子。图像、Markdown、代码、PDF、文件夹、失效引用和损坏图片均由本地示例生成，不引用用户文件。

入口正常结束时输出 `capture-manifest.json`。每张图片默认标记 `pending-human-or-agent-image-inspection`；任何预览错误均在对应 manifest 项保留。`capture-error.txt` 代表截图任务出现错误，需要修复重跑。若 PDF 预览状态误显示组件缺失，应修复 DLL 加载后再验收，不可把错误页当成 PDF 成功截图。

## 2026-10-25 单例、托盘与响应修复

原生探针复现管理窗口回调中再次导航创建第二个 HWND。现在延后导航至回调释放借用，已有句柄更新失败也不创建重复窗口。管理、快捷、设置、引导、托盘五类窗口重复打开均复用原始 HWND；关于页面复用设置窗口。标题栏下拉菜单禁用当前窗口的导航，关于页面同时禁用关于入口。

Windows 托盘改为 GPUI 菜单，跟随应用主题。开启记录时显示暂停图标与“暂停记录”，暂停后显示播放图标与“开启记录”。后台原子切换读取最新状态，已排队的采集也检查暂停状态。其他平台保留原生菜单。

置顶、最近复制的数量紧跟分组标题。置顶与收藏按主键更新单条记录；未超容量时局部刷新快照，避免每次扫描历史全表。超容量仍执行清理规则。2001条合成加密记录的单条更新中位耗时由25.9ms降至3.7ms；这是数据库基准，不是点击至显示的端到端耗时。

验证：14项核心测试通过，另一个延迟基准按需运行通过；2项UI测试通过；Clippy全目标零警告，默认Debug构建通过。首次尺寸与五类窗口单例原生探针通过。生成88张原生图，抽查默认明暗托盘、暂停状态、当前导航禁用与分组数量。截图生成不等于全部主题视觉验收；真实系统托盘鼠标操作、高DPI及非Windows平台仍需实机验证。
