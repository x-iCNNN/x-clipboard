# 加密数据库缩略图（2026-10-25）

图片缩略图保存在同一个 Turso AES-256-GCM 数据库的 clip_thumbnails 表，以历史记录 ID 为主键，与原始 payload 分开读取，不产生明文缓存文件。

- PNG 格式，保持透明通道，最大 96×64 像素；编码结果限制为 32 KiB，解码后的 RGBA 像素最多 24 KiB。
- 新图片先保存所有原始格式，再通过有界后台队列生成并保存缩略图，不在 UI 或数据库写入线程解码原图。任务忙或退出前未完成时，首次列表请求会补齐。
- 已有记录不在启动时批量扫描或解码，首次需要时生成并落库。之后列表直接读取小 PNG，命中时不读取原始 payload。
- 重复复制复用同一记录 ID 和缩略图。原始格式、内容指纹、完整预览及粘贴路径不变。
- 列表 RAM 缓存仍最多 48 张；关窗休眠时清空 RAM，后台生成结果只保存 DB，不重新填充休眠中的界面缓存。
- 删除、清空、自动清理在事务中清理缩略图；后台晚到的结果仅在原记录仍存在时写入，不会复活已删除的数据。
- 编解码尺寸和分配受限；无效小图会尝试从原始载荷重新生成。缩略图只是预览，不能恢复损坏或丢失的原始内容。

验证：18 项核心测试、2 项 UI 测试、Clippy、默认 Debug 构建通过；原生快捷面板浅深完整截图已检查。覆盖 PNG 小图尺寸/透明通道/畸形数据限制、DB 与 WAL 无明文缩略图、错误密钥、加密重开、重复复制、保护内容保留、删除/自动清理/晚到结果，以及关窗卸载后重新读取。

存储测试主动破坏原始 payload 后，小图仍可独立读取与解码，验证其不依赖原始载荷。服务测试确认无窗口时生成后不填充 RAM 缓存，重新打开可读到已保存的小图。

生成或补齐时仍需解码原图一次，因此会有短暂 CPU/内存开销；列表缓存命中后只需小图。缩略图体积计入数据库实际磁盘占用，不计入原始内容容量。此前 dist 中的 Release/UPX 包未在本轮重打包。
