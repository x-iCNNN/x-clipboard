# 后台按需卸载（2026-10-25）

本轮保持界面布局，修改关闭后的生命周期。最新默认 Debug 包含本轮改动；此前 dist 里的 Release/UPX 属于上一轮构建。

## 实现

- 首次打开窗口才初始化 GPUI Kit 组件和内置主题。
- 关闭后先隐藏；1 秒内快速重开复用原窗口，超过 1 秒销毁内容窗口、Desktop、编辑器、列表和图像资源。同类窗口同时至多一个，销毁后按需重建。
- 使用 QuitMode::Explicit，最后一个内容窗口销毁不会退出。托盘、快捷键、剪贴板后端和加密写入继续运行。
- 隐藏窗口停止同步历史快照。最后一个历史消费者关闭后，服务卸载整份历史列表、搜索集合、预览和缩略图。迟到的异步结果不能填回休眠缓存。
- 后台只读取轻量统计。加密覆盖索引 clips_retention 提供标志、顺序、字节数和 ID，避免每次保存反序列化整张历史表。置顶、收藏和双阈值保留规则不变。
- 重开异步加载最新历史，期间显示“正在加载历史…”。Windows 快捷面板重建仍按 360×540 隐藏初始化后不激活显示。

## 验证

服务回归先红后绿：后台不加载历史、关闭释放快照、后台保存、重开读取新记录、保护状态持久化。15 项核心测试、2 项 UI 测试和 Clippy 通过；延迟微基准本轮未重复。

原生探针验证：三个内容窗口及图片预览打开后全部关闭，GPUI 内容窗口数、Desktop 实体数和历史缓存行数均为 0；快速重开保持单例，销毁后重建 3 次，宽度正确且历史恢复。

采集合成记录测试走真实存储服务命令，探针关闭系统后端；不等同于本轮重新验证真实应用的系统剪贴板和钉钉回贴。macOS/Linux 未实机验证。

## 内存实测与边界

同一暂停采集的合成库、默认 Debug、后台冷启动，预热 5 秒并采样 10 次取中位数：

| 构建 | 工作集 | 私有内存 |
|---|---:|---:|
| 改前 | 86.4 MiB | 52.1 MiB |
| 改后 | 62.3 MiB | 51.5 MiB |

工作集下降不等于已提交私有内存等量下降。此处私有内存变化很小，不能声称后台堆占用大幅降低。

以下热用采样来自 ui-capture 诊断构建，与默认 Debug 冷启动不是同一构建口径：

| 阶段 | 工作集 | 私有内存 |
|---|---:|---:|
| 三窗口与图片预览 | 169.4 MiB | 192.4 MiB |
| 首次全部关闭 | 153.7 MiB | 166.2 MiB |
| 三次重建并关闭后 | 157.2 MiB | 139.9 MiB |

虽然内容窗口和历史缓存均已卸载，用过界面后的进程占用仍高于冷启动，不能承诺回到纯监听最低内存。框架全局资源、图形驱动及分配器保留开销尚未分别归因。

Windows 堆资源整理实验没有观察到有意义的私有内存回收，未纳入生产代码。API 行为参考 [Microsoft HeapSetInformation](https://learn.microsoft.com/en-us/windows/win32/api/heapapi/nf-heapapi-heapsetinformation)。

更彻底的下一档架构是独立监听进程与按需启动的 UI 进程，最后一个窗口关闭后退出 UI 进程。需要受保护 IPC、命令确认及快捷键/焦点回贴的跨进程回归，本轮未实现进程拆分。

原始数据：test-data/dormancy-cold-before.json、dormancy-cold-after.json、dormancy-native-final/dormancy-result.json。原生复现：ui-capture 构建、合成 fixture、--ui-review，并设置 X_CLIPBOARD_UI_REVIEW_DORMANCY=1。
